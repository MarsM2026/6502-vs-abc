# Modern tools versus the 1975 6502

Question: the real 6502 was laid out by hand at MOS Technology in 1975. How does it
compare with what Yosys, ABC and our evolutionary optimiser make of a modern Verilog 6502?

## Data

The visual6502 project (Greg James, Brian Silverman, Barry Silverman, 2010) photographed
a 6502 die and extracted its complete transistor netlist. We use the copy in
[perfect6502](https://github.com/mist64/perfect6502) (`vendor/perfect6502/netlist_6502.h`).
That data is **CC BY-NC-SA 3.0**: non-commercial use only, credit Greg James and
www.visual6502.org. See `vendor/perfect6502/COMMIT`.

## What is in the real chip ([src/nmos.py](../src/nmos.py))

The 6502 is NMOS logic. A *static gate* is a node with a depletion-mode pull-up (a resistor
to VCC) and a pull-down network of enhancement transistors to ground. It computes NOT(f),
where f is the series (AND) / parallel (OR) combination of the transistors' inputs. Besides
those there are *pass transistors* (switches between two signal nodes: dynamic latches,
multiplexers, the internal buses) and *push-pull drivers* (a transistor to VCC plus one to
ground, for the address/data pins and other heavily loaded signals).

`python src/nmos.py` classifies every transistor:

| Part | Count |
|---|---:|
| Nodes | 1,725 |
| Enhancement transistors | 3,288 |
| Depletion pull-ups | 1,018 |
| **Total transistors** | **4,306** |
| Static gates (one per pull-up) | 1,018 |
| … transistors in their pull-down networks | 2,242 |
| … as two-input gates (k transistors → k−1 gates, k = 1 → NOT) | 1,769 |
| Pass transistors | 622 |
| Push-pull drivers: to VCC / to ground | 178 / 231 |
| Other transistors to ground (clearing dynamic nodes) | 15 |

Pull-down size distribution (transistors per static gate): 1: 545, 2: 206, 3: 99, 4: 44,
5: 36, 6: 24, 7: 28, 8: 32, 9: 4. The wide gates (7–9) are most likely the instruction
decode PLA.

The commonly quoted figure of 3,510 transistors is for the whole die as photographed; the
perfect6502 netlist has 3,288 enhancement transistors (some unused or merged devices are
left out).

## Our designs in the same technology ([src/nmos_map.py](../src/nmos_map.py))

Counting two-input gates is not a fair comparison with a transistor netlist. So we write an
NMOS cell library (INV, NAND2–4, NOR2–8 and AOI/OAI complex gates up to 6 inputs, area =
pull-down transistors + 1 pull-up) and let ABC map each netlist onto it, minimising area
(`map -a`). A flip-flop is counted as a two-phase dynamic master-slave latch:
2 pass transistors + 2 inverters = 6 transistors.

| Design | NMOS cells | Combinational transistors | Flip-flops × 6 | Total |
|---|---:|---:|---:|---:|
| Arlet's core, straight from RTL | 1,499 | 5,119 | 858 | 5,977 |
| Yosys + ABC once (2,075 two-input gates) | 1,495 | 5,091 | 858 | 5,949 |
| ABC iterated (1,994 gates) | 1,468 | 4,989 | 858 | **5,847** |
| Our best, evolved (1,963 gates) | 1,501 | 5,060 | 858 | 5,918 |
| **Real 6502 (MOS, 1975)** | 1,018 static gates | | | **4,306** |
| Real 6502 without its push-pull pin drivers | | | | 3,897 |

**Correction (stronger ABC settings).** The table above uses ABC's `map -a`. ABC's area
mapper `amap` does much better on this library, and `&deepsyn` before mapping better still
(`results/logs/amap-sweep.log`, `amap-deepsyn.log`; every row below passes Klaus Dormann's
test after expanding the cells back to gates):

| Design | Combinational | Total |
|---|---:|---:|
| ABC iterated, `map -a` (old best, above) | 4,989 | 5,847 |
| ABC iterated, `amap -F 8 -A 16` | 4,446 | 5,304 |
| ABC + deepsyn (ABC chain only), `amap` | 4,063 | 4,921 |
| Our evolved netlist + deepsyn, `amap` | 4,014 | 4,872 |
| … + cell-level window CGP ([src/cell_windows.py](../src/cell_windows.py)) | 4,009 | 4,867 |
| Evolved + deepsyn, `amap` onto the library with wide gates (`--lib wide`) | 3,933 | 4,791 |
| … + 134 pass-transistor multiplexers ([src/pass_rewrite.py](../src/pass_rewrite.py)) | 3,799 | 4,657 |
| … + 43 pass-transistor buses and 27 bus-sharing latches ([src/bus_rewrite.py](../src/bus_rewrite.py)) | 3,626 | **4,484** |
| **Real 6502** | | **4,306** |

With static gates only, the gap to the 1975 design is 13% (4,867 vs 4,306), not 36%. With
the techniques the real chip uses (wide gates, pass-transistor multiplexers, buses and
latches that absorb them), it shrinks to **4%** (4,484 vs 4,306); without the real chip's
pin drivers (3,897) it is 15%.

**Wide gates and pass-transistor multiplexers** (`results/logs/pass-cells.log`).

* *Wide gates* (`python src/nmos_map.py --lib wide`): NOR gates up to 16 inputs and
  AND-OR-INVERT gates with up to 8 two-transistor branches. They are ordinary static NMOS
  (all pull-downs in parallel, so width costs only area); the 6502's decode PLA is a NOR
  plane built this way. ABC ignores gates with more than 15 inputs; it uses 27 AOI2222
  and 19 AOI22222. 4,872 → 4,791.
* *Pass-transistor multiplexers* (`MUX2I = !(s ? a : b)`): two pass transistors gated by
  s and !s, plus an inverter that restores the level an NMOS pass transistor loses, so 4
  transistors. The select complement costs one more inverter (2) unless the netlist already
  has it; `mux_select_cost()` charges that once per select signal. ABC's `amap` ignores
  cells whose function is not monotone, and `map -a` uses the mux but maps everything else
  much worse (5,129 at best). So `src/pass_rewrite.py` maps with `amap` and then replaces
  every AOI22/OAI22 that is a multiplexer (one input is the other's inverse through an INV)
  by a MUX2I. That rewrite is exact. 134 cells, all with the select inverter already
  present: 4,791 → 4,657. The cell netlist, expanded back to gates, passes Klaus
  Dormann's test.

**Pass-transistor buses and bus-sharing latches** (`src/bus_rewrite.py`,
`results/logs/bus-rewrite.log`). These two depend on which states the chip can reach,
so they need a proof, not just a cell function:

* *Bus.* An AND-OR-INVERT `!(s1&d1 | s2&d2 | ...)` can be one pass transistor per branch
  onto a shared node, plus a transistor that discharges the node in the other clock phase
  and the restoring inverter: n + 3 instead of 2n + 1. That is only correct if at most
  one select is 1 at a time. `bus_rewrite.py` proves it with SAT: the netlist's clauses,
  the register invariants of `src/invariants.py` (322 proved for this netlist, valid in
  every reachable state) and all primary inputs free. It tries both literals of each
  branch as the select. If exactly one select is always 1, the discharge transistor is not
  needed (n + 2). 43 cells qualify: 25 with exactly one select (decoder outputs), 18 with at
  most one. 4,657 -> 4,539. The register invariants add nothing here; every proof already
  follows from the logic.
* *Latch.* A pass-transistor mux whose only load is one flip-flop moves into the
  flip-flop's master stage: the master pass transistor becomes two, gated by
  (phi1 & s) and (phi1 & !s), and the flip-flop's own inverters restore the level. The mux
  then costs 1 transistor instead of 4, but each select needs two gated clock signals (two
  NOR2, 6 transistors), so it pays off from 3 latches per select (a register loaded as a
  whole). 27 muxes in such groups: 4,539 -> **4,484**.

Both rewrites keep every cell's function, so the rewritten netlist simulates exactly like
the static one; its expansion passes Klaus Dormann's test. What the proof assumes is the
usual two-phase discipline of the real chip: selects and data are stable while the clock
phase that uses them is active. A variant that lets ABC price wide AOIs as buses
(`--lib busopt`) ends worse (4,572), because the mapping then has no latch muxes.

## Findings

1. **The 1975 hand design still wins, but only just.** With static gates only, the best
   automated result is 13% larger than the real chip (4,867 vs 4,306). Giving the
   automated flow the real chip's techniques (wide gates, pass-transistor multiplexers,
   proved buses, latches that absorb muxes) brings it to 4,484, 4% larger (15% if you
   discount the real chip's pin drivers, which our designs do not have at all). (First
   measured as 36% with ABC's weaker `map -a`; see the correction above.)
2. **Fewer two-input gates is not fewer transistors.** Our evolved netlist has the fewest
   two-input gates, but in NMOS it needs 71 more transistors than the ABC-iterated one.
   The CGP fitness counted gates; the technology counts transistors. The −1.6% we found
   does not carry over to the real cost.
3. **Where MOS gets its advantage** (likely, not yet measured one by one):
   * pass-transistor logic: 622 pass transistors make multiplexers, latches and bus
     connections that cost several static gates each in our library;
   * dynamic logic and precharged buses: the internal buses are precharged and pulled
     down, so one bus serves many sources;
   * the decode PLA: a regular NOR array instead of random logic;
   * complex gates with up to 9 transistors in one pull-down network.

## Caveats

* Arlet's core is not the same machine as the real 6502. It expects synchronous RAM, is not
  cycle-exact, has no SYNC/SO/φ1/φ2 pins, and has no clock generator. The real chip
  contains all of these.
* The 6-transistor flip-flop and the cell library are estimates of what an NMOS designer
  could use, not a calibrated process.
* ABC's mapping is heuristic. A better mapper would find a somewhat smaller result.

## Evolution with an NMOS cost (src/nmos_cost.py)

The window optimiser counted two-input gates. [src/nmos_cost.py](../src/nmos_cost.py) is a
fast estimate of NMOS transistors instead. A non-inverting AND/OR with fan-out 1 is absorbed
into the complex gate that reads it (that is how AOI/OAI gates form), and XOR/XNOR cost 7.
On whole netlists the model is about 15% above ABC's mapping, but it ranks the netlists in
the same order. `windows.py --cost nmos` uses it as the CGP size measure. A replacement is
only accepted if the estimate for the *whole* circuit drops, because a local gain can break
an absorption just outside the window. `nmos_map.py --structural` maps without ABC's
restructuring, so it shows whether the evolved structure itself is cheaper.

**Run:** from the ABC-iterated netlist (1,994 gates), one pass, k = 13, up to 40 gates per
window, don't-cares, seed 8 (`results/logs/windows-nmos.log`, 3 h 40 min). 2,175 windows,
53 replacements accepted, 13 rejected because they created a loop. The result
`build/cpu_nmos.json` passes Klaus Dormann's functional test (96,241,383 cycles).

| Netlist | Two-input gates | nmos_cost estimate | ABC `map -a` | ABC structural |
|---|---:|---:|---:|---:|
| ABC iterated (start) | 1,994 | 5,710 | **5,847** | 5,944 |
| Evolved for gates (best gate count) | 1,963 | 5,936 | 5,918 | 6,338 |
| Evolved for NMOS cost | 2,001 | **5,646** | 5,878 | **5,916** |

(Totals including 143 flip-flops × 6 transistors.)

* The CGP did what it was asked: the estimate fell by 64 transistors (−1.1%) while the gate
  count *rose* by 7. It traded gates for structures that absorb into complex gates.
* Mapped without restructuring, the evolved structure is the cheapest of the three
  (5,916 vs 5,944): the gain is real in the structure itself.
* With ABC's full restructuring (`dc2`, `dch`) the gain disappears: ABC on its own netlist
  still gives the best result, 5,847. ABC rebuilds the structure before mapping, so what
  matters is how the netlist responds to that, not how it looks going in.
* Conclusion: an NMOS-aware cost fixes the problem from the gate-count run (5,918 → 5,878),
  but it does not beat a good mapper. To win, the evolution would have to work on the
  mapped cell netlist itself, with the real cell library as its gate set.

### Evolution directly on the NMOS cells (src/cells.py, src/cell_windows.py)

So we tried exactly that. `cells.py` reads ABC's mapped netlist back (Yosys JSON) and can
expand it to two-input gates for SAT and simulation. `cell_windows.py` runs window CGP whose
nodes *are* library cells (INV, NAND2–4, NOR2–8, AOI/OAI up to 6 inputs) and whose cost is
their exact transistor count, with SAT don't-cares. Nothing is re-mapped afterwards, so
every accepted replacement is a real saving.

Run from the best mapping (our evolved netlist + deepsyn + `amap`, 4,872 transistors), k = 12,
up to 20 cells per window, 2,000 generations (`results/logs/cells-opt.log`, 65 min):
968 windows, 3 improved, 2 rejected for loops: **4,872 → 4,867** transistors. The result
passes Klaus Dormann's test.

So ABC's `amap` leaves almost nothing for local search on windows of up to 20 cells. The
remaining distance to the real chip is not in local cell choice but in the techniques the
1975 design uses and our library cannot express: pass transistors, precharged buses and
dynamic logic.

## A gate-level model of the real 6502 (src/real6502.py)

Goal: a netlist of ordinary gates that behaves exactly like the transistor netlist, so it
can run Klaus Dormann's test and be optimised like any other netlist.

**Reference.** perfect6502's switch-level simulator, built from `vendor/perfect6502` with a
small harness ([tools/ref6502/klaus_ref.c](../tools/ref6502/klaus_ref.c)). It records the
pins after every half-cycle (AB, DB, R/W, clock) for lockstep comparison. On this machine it
runs about 1,600 half-cycles per second, too slow for the whole test (many hours to days),
so we compare against the first 200,000 half-cycles (about 100,000 clock cycles), which
cover the reset sequence and the start of the test program.

**Semantics.** In perfect6502, nodes joined by conducting transistors form a group that
takes one value, by priority: GND → 0, VCC → 1, pin forced low → 0, pull-up → 1, a node
that was high (stored charge) → 1, otherwise 0.

**Conversion.**
1. Series/parallel pull-down networks through internal nodes (157 nodes that drive no gate,
   each belonging to exactly one network) become one "conducts to GND" expression.
2. The remaining 622 transistors between signal nodes are pass switches. They form
   channel-connected components (CCCs): 785 single nodes, 196 pairs (latches), and a few
   larger ones up to 48 nodes (the ALU result multiplexer). For each node and each priority
   class we build "reachable through conducting switches within the CCC" logic, with as
   many propagation rounds as the CCC's diameter.
3. Stored charge and combinational feedback (cross-coupled gates) use the node's value from
   the previous *settling step*: a register per such node. One settling step is then a
   plain synchronous circuit. The harness ([src/csim_real.py](../src/csim_real.py)) repeats
   steps until no register changes, after every input change, with perfect6502's bus
   protocol (memory served on the rising edge of clk0).

**Result.**

| Netlist | Gates | Registers | Lockstep vs perfect6502 (200,000 half-cycles) |
|---|---:|---:|---|
| Direct conversion | 24,557 | 907 | identical after reset (12 differences in the first 10 half-cycles) |
| After one ABC run | 8,888 | 556 | identical after reset; full Klaus test PASS |

The only differences are the first few half-cycles after power-on: the stack pointer starts
at $00 in our model and at $C0 in perfect6502. Power-on register contents are undefined in a
real 6502 and depend on the simulator's evaluation order. The test program sets the stack
pointer itself, and from then on every address, data byte and R/W level matches. On average
a step needs about 4 settling iterations (maximum 6). It never failed to settle.

**Full functional test.** The 8,888-gate version passes Klaus Dormann's complete
functional test: `PASS cycles=96241378`, in 6 h 18 min (about 8,500 half-cycles per second;
`results/logs/real6502-klaus.log`). On average a half-cycle needed 3.69 settling steps,
at most 6, and the model never failed to settle. perfect6502 itself would need more than
a day for the same run. Arlet's core passes the same test after 96,241,383 cycles; the
5-cycle difference comes from the different reset and start-up sequence.

So the conversion is a working 6502: a static-gate netlist with settling registers that
runs the whole test, built mechanically from the 1975 transistor netlist.

### Optimising the real chip's model

Same method as for Arlet's core: iterate ABC to a fair baseline, then window CGP with SAT
don't-cares (k = 12, up to 30 gates per window, seed 9), then ABC again. Every netlist is
checked in lockstep against perfect6502 (200,000 half-cycles, no differences after reset).

| Netlist | Gates | Registers | Check |
|---|---:|---:|---|
| Direct conversion | 24,557 | 907 | lockstep |
| ABC once | 8,888 | 556 | lockstep, full Klaus test PASS |
| ABC 4× | 7,705 | 527 | lockstep |
| ABC iterated to its plateau (best of 24 runs) | 7,416 | 525 | lockstep |
| ABC 4× → window CGP (one pass) | 7,345 | 527 | lockstep |
| … → ABC 4× more | **7,150** | 513 | lockstep, full Klaus test PASS (96,241,378 cycles) |

Logs: `results/logs/real6502-win.log` (windows: 7,650 windows, 176 accepted, 6 rejected for
loops, 18.6 h) and `results/logs/real6502-abcx.log` (ABC iterations and checks).

* ABC converges slowly on this model: 8,888 → 7,705 in four runs, then it drifts between
  7,416 and 7,438 from run 12 to run 24. That plateau is the fair baseline.
* One window pass alone beats it a little (7,345, −1.0%). Window CGP followed by ABC gives
  7,150, **−3.6% beyond converged ABC**: more than on Arlet's core (−1.6%). The windows
  move ABC out of its local minimum, as we saw before.
* This shrinks the *simulation model*, not the 1975 layout (see below). Most of the gain is
  probably in the logic that the conversion generates mechanically: the CCC reachability
  rounds and pull-down expressions, which contain a lot of redundancy.

### Correction: ABC's `&deepsyn`, and where the gain comes from

"Converged ABC" above is ABC's default script iterated. ABC's slower `&deepsyn` search
(randomised restructuring with SAT-based resynthesis) does far better on this model
(`results/logs/real6502-deepsyn.log`):

| Netlist | Gates | Registers | Check |
|---|---:|---:|---|
| ABC default script, plateau | 7,416 | 525 | lockstep |
| Our windows + ABC | 7,150 | 513 | full Klaus test PASS |
| `&deepsyn` 2 min on the plateau | 5,257 | 469 | lockstep |
| `&deepsyn`, 5 more runs of 5 min | 4,934 → 4,790 → 4,769 → 4,750 → **4,721** | 446 | lockstep |

So the mechanical conversion contained almost half redundant logic (8,888 → 4,721), and
the default ABC script and our windows found only a small part of it. The −3.6% above was
measured against a weak baseline. Registers disappear as well: prev registers whose value is
no longer read are swept.

Where does the window gain come from? Three measurements:

1. **Don't-cares, not the evolution itself.** The same window run (seed 9, 1,000 windows)
   without SAT don't-cares improves 6 windows (−9 gates); with don't-cares 35 windows
   (−53 gates). About 85% of what the windows find relies on input combinations that cannot
   occur (`results/logs/real6502-nodc.log`).
2. **ABC's own don't-care resynthesis does not find it.** `if -K 6; mfs2 -a` on the plateau
   gives 7,444 gates, no gain. `mfs2` uses windowed don't-cares too, but smaller windows and
   no evolution.
3. **Deepsyn finds far more**, because it searches much deeper: it restructures big parts of
   the network many times and keeps what SAT proves equal. The redundancy in the conversion
   is mostly *structural*: the per-node reachability logic of the CCCs and the pull-down
   expressions repeat the same subterms in forms the default script cannot merge.

On Arlet's core (README stage 3f) the window evolution does still add about 1% on top of
deepsyn, probably through the register-state invariants. The same holds for the real
chip's model (`results/logs/real6502-dwin.log`):

| Route from the 4,721-gate deepsyn netlist | Gates | Check |
|---|---:|---|
| 2 more deepsyn runs (control, deep 7 and 8) | 4,691 | lockstep 200k half-cycles, 0 mismatches |
| windows (k=12, ≤30 gates, don't-cares; 4,095 windows, 10 improved, 8.3 h) | 4,711 | |
| windows, then 2 deepsyn runs | **4,633** | lockstep 200k half-cycles, 0 mismatches; full Klaus test PASS (96,241,378 cycles), 444 flip-flops |

The windows themselves remove only 10 gates, but they change the structure enough that
the next deepsyn runs find more: 4,633 against 4,691 for deepsyn alone, 1.2% smaller.
That matches the ~1% on Arlet's core. Window evolution is a small but real addition to
the strongest ABC script, not a replacement for it.

### Register correspondence (`scorr`)

So far every ABC run treated the flip-flops as boundaries: Yosys hands ABC only the
combinational logic. With `abc -dff` the registers go to ABC too, and ABC's `scorr`
proves by induction which registers (and internal signals) are equal or constant in every
state reachable from the start state, and merges them. That needs the start state, so
`src/reabc.py --init-zero` declares every register with initial value 0, as in the
simulators.

The proof is valid for the settling simulation too. `scorr` proves equality for *every*
input sequence from the all-zero state, and settling is one such sequence: inputs held
fixed while the registers are clocked until nothing changes. Equal registers therefore
take equal values at every settling step, and the merged circuit settles the same way.

| Run (from the 4,633-gate netlist) | Gates | Flip-flops |
|---|---:|---:|
| `scorr` + fast mapping (12 s) | 4,004 | 425 |
| control: same script without `scorr` | 4,638 | 444 |
| `scorr -F 4` (4-step induction) | 3,969 | 425 |
| `scorr` → deepsyn (5 min) → `scorr` | 3,824 | 421 |
| … again | 3,729 | 414 |
| … with `scorr -F 4` | 3,687 | 414 |
| … with `scorr -F 8`, 3 more rounds | 3,675 → **3,667** → 3,672 | 414 |

Every row runs in lockstep with perfect6502 (200,000 half-cycles, 0 mismatches;
`results/logs/real6502-scorr.log`, `real6502-scorr2.log`). The 3,687- and 3,667-gate netlists also pass Klaus Dormann's full functional test
(96,241,378 cycles; `real6502-scorr-klaus.log`, `real6502-scorr5-klaus.log`).

**This is the largest gain after deepsyn: 4,633 → 3,667, −21%.** The conversion creates a
settling register for every node that can store charge, and many of them always hold the
same value as another register, or the same value as a combinational signal. Merging those
also removes the logic that computed them. ABC's combinational scripts, and our windows,
cannot see this, because they treat every register output as a free input. Our
register-state invariants (README stage 3e) were the start of this idea; `scorr` does it
fully.

On Arlet's core the same `scorr` merges only 1 register (1,822 → 1,811, against 1,816 for
the control): hand-written RTL has hardly any redundant registers.

**What the gate count means.** 8,888 gates is not "the 6502 in gates". It is a *simulation
model* that expresses pass transistors, precharged buses and stored charge with static
gates and settling registers. Shrinking it says something about the model, not directly
about the 1975 layout.

## Possible next steps

* Measure each MOS technique: count the transistors of the decode PLA, the bus drivers and
  the register file separately.
* Let the mapper itself build buses. ABC cannot, because it does not know which selects
  exclude each other; a mapper that gets the proved exclusions as input could build wider
  buses than the AOIs ABC happens to produce.
* Wider pass-transistor multiplexers (mux trees) and pass-transistor XOR.
