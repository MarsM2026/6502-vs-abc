Why not from random?

A CPU has no gentle slope

A random netlist executes no instructions, and neither do its mutants, so there is almost no partial credit for evolution to climb. In research on evolving circuits from scratch, progress stalls at about the size of a 4×4-bit multiplier. The 6502 has roughly 3,500 transistors and many internal states.

What does work

Seed, then shrink

Start from a correct 6502 netlist, keep the registers fixed, and evolve only the combinational logic between them. Each block is checked exhaustively or with a SAT-based equivalence checker, so evolution can only remove gates, never break behaviour. Published work using this method has cut gate counts by tens of percent.

The loop

Selection → variation → fitness

  1. EncodeEach candidate is a netlist of AND/OR/XOR/NAND/NOR/XNOR/NOT gates (Cartesian Genetic Programming).
  2. SimulateEvaluate every input combination at once, bit-parallel, so fitness is exact rather than sampled.
  3. ScoreCorrect output bits first; only once fully correct, fewer gates wins.
  4. VaryOne parent, four mutated children per generation; unused gates drift freely.
  5. RepeatOnce fully correct, the circuit can only stay correct while getting smaller.

Long-term plan

Milestones

01

Small blocks

Evolve adders and a 4-bit ALU slice from random gates and from hand-built seeds. Running: a 4-bit adder has been evolved from random gates.

02

Real 6502 netlist

Synthesise an existing Verilog 6502 to gates with Yosys. Done: 3,026 gates and 143 flip-flops; passes Klaus Dormann's full functional test.

03

Cut at registers

Cutting at the registers proved too coarse (most logic is shared), so instead small windows of ≤ 10 inputs are cut out anywhere in the netlist. Done.

04

Seeded optimisation

Shrink each window with evolution, checked on every input combination. Result: the ABC-optimised 6502 (2,075 gates) was shrunk further to 2,021 gates and still passes the full functional test, mostly thanks to SAT don't-cares (input combinations no CPU state can produce). But ABC itself also improves when rerun: iterated, it plateaus around 1,994 gates. Against that fairer baseline, window evolution with don't-cares still removes another 26 gates (1,994 → 1,968, −1.3%), still passing the full functional test. Register-state don't-cares (322 SAT-proven invariants about which flip-flop combinations can occur) took it to 1,963 (−1.6%). Correction: ABC's slower &deepsyn search reaches 1,896 gates in 2 minutes (passes the test) and 1,865 in 10. Measured against that, window evolution does not beat ABC.

05

Versus 1975

Compare with the real 6502's transistor netlist (visual6502). Result: counted in NMOS transistors, the best automated design (ABC with &deepsyn and amap, plus evolution) needs 4,867 transistors; the hand-drawn original needs 4,306. MOS wins by about 13% (first measured as 36% with weaker ABC settings), thanks to pass transistors, precharged buses and the decode PLA. Evolving with a transistor cost instead of gates helps a little (5,918 → 5,878), but does not beat ABC's own mapping. A mechanical gate-level conversion of the real chip (8,888 gates) passes the full functional test; window CGP + ABC shrinks it 3.6% beyond converged ABC (7,416 → 7,150 gates).

06

Full-CPU validation

Reassemble the blocks and pass Klaus Dormann's 6502 functional test suite.

Out of scope: the 6510 (the C64 variant with an on-chip I/O port) and other 6502 variants such as the 6507. The target is the plain 6502 core only.
