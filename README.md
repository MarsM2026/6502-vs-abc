# 6502 vs ABC — evolving a 6502 at gate level

An experiment in evolving real gate-level circuits with a genetic algorithm (Cartesian
Genetic Programming), up to the logic of a complete 6502 CPU, measured honestly against the
logic optimiser ABC (via Yosys) and against the real NMOS 6502 from 1975.

**Short answer.** Window evolution with SAT don't-cares beats ABC's *default* script
(1,994 → 1,963 gates), but not ABC's `&deepsyn` (1,837). Combined, evolution followed by
deepsyn gives the best result: **1,822 gates**, all passing Klaus Dormann's functional test.
In NMOS transistors the best automated design needs 4,867; the hand-drawn 1975 chip 4,306.

The tested netlists are in [results/netlists/](results/netlists/); everything under
`build/` is generated by the scripts and not in the repository.

There are two separate things in this repository:

| Part | What it is |
|------|-----------|
| `src/evolve.py`, `index.html`, `assets/` | Pedagogical toy / browser demo. **Not** a circuit simulator. |
| `src/cgp.py` and friends | Real gate-level evolution: every candidate is a netlist of AND/OR/XOR/NAND/NOR/XNOR/NOT gates, simulated exhaustively. |

Requires Python 3.10+ and nothing else.

## Running

From the project root:

```sh
# Evolve a 2-bit adder from random gates (seconds to a minute)
python src/evolve_circuit.py --target adder2

# Evolve a 4-bit adder from random gates (slower; may need more generations)
python src/evolve_circuit.py --target adder4 --gens 300000

# Seeded mode: start from a textbook ripple-carry adder (20 gates) and let evolution shrink it
python src/evolve_circuit.py --target adder4 --seeded --gens 50000

# A 6502-flavoured 4-bit ALU slice (ADC/AND/ORA/EOR + carry + zero flag)
python src/evolve_circuit.py --target alu4 --nodes 200 --gens 500000

# Reproducible run
python src/evolve_circuit.py --target adder3 --seed 1234
```

Each run prints progress, the final netlist, and saves `results/<target>-<mode>-<seed>.v`
(Verilog) and `.json` (genome + fitness history).

Useful options: `--nodes` (genome size / max gates), `--lam` (children per
generation), `--stop-when-correct` (stop at the first working circuit instead of
continuing to minimise gates).

## Layout

(Key scripts added in stage 3–4: `src/windows.py`, `src/dontcare.py`, `src/invariants.py`,
`src/reabc.py`, `src/nmos.py`, `src/nmos_map.py`; third-party code and data in `vendor/`.)

- `src/cgp.py` — genome representation, gate set, bit-parallel simulation, mutation, netlist/Verilog export
- `src/targets.py` — target truth tables (`adder1`..`adder4`, `alu4`)
- `src/seeds.py` — hand-built correct circuits for seeded runs
- `src/circuit_evolution.py` — the (1+λ) evolution loop and fitness function
- `src/evolve_circuit.py` — command-line runner

## Gate-level 6502 (stage 2)

Needs `pip install yowasp-yosys` and a C compiler (clang or gcc).

```sh
yowasp-yosys -s synth/synth_6502.ys   # Verilog -> build/cpu_gates.json
python src/csim.py                    # netlist -> C, run Klaus Dormann's functional test (~6 min)
```

- `vendor/verilog-6502/`: Arlet Ottens' Verilog 6502 (his licence notice is in `cpu.v`)
- `vendor/klaus-functional-tests/`: Klaus Dormann's 6502 functional test (GPL-3, see `license.txt`)
- `src/netlist.py`: loads the Yosys netlist into our gate set plus D flip-flops
- `src/csim.py`: compiles the netlist to C. This is a deliberate exception to "plain Python",
  because the test runs ~96M clock cycles and pure Python would take hours.

Result (2026-11-22): **3,026 gates + 143 flip-flops, passes the full functional test in 96.2M cycles.**
Breaking single gates makes it fail, so the PASS isn't a false positive.
Caveat: ABC (Yosys' optimiser) crashes in the WebAssembly build here, so the netlist is synthesised
with `-noabc` and is less optimised than it could be.

## Window optimisation of the 6502 (stage 3)

```sh
python src/cones.py                                   # structure analysis
python src/windows.py --passes 2                      # ~90 min -> build/cpu_opt.json
python src/csim.py --netlist build/cpu_opt.json       # validate
```

Cutting at the flip-flops turned out to be too coarse: only 57 of 168 cones have ≤ 20 inputs,
and 761 gates are shared by more than 10 cones. `src/windows.py` instead cuts out small
windows (≤ 10 inputs, ≤ 25 gates) anywhere in the netlist, evolves each one smaller with CGP
(checked on all input combinations), and splices it back. Exact equivalence per window
guarantees the whole CPU is unchanged.

Result (2026-11-22, seed 1):

| Stage | Gates | Functional test |
|---|---:|---|
| Yosys `-noabc` netlist | 3,026 | PASS |
| After structural cleanup (constants, duplicates, double NOT) | 2,934 | |
| Window CGP, pass 1 (3,058 windows, 200 improved, 50 min) | 2,628 | |
| Window CGP, pass 2 (2,557 windows, 10 improved, 39 min) | 2,613 | |
| Final cleanup | **2,609** | **PASS**, identical 96,241,383 cycles |

Evolution removed 325 gates (11.1%) beyond the cleanup, 13.8% overall. Pass 2 found almost
nothing, so the search has hit a local optimum for this window size.
**Caveat:** the baseline is not ABC-optimised (ABC crashes in the WebAssembly Yosys), so part
of this gain is probably something a conventional optimiser would also find.

### Honest baseline: ABC (stage 3b)

ABC works in the native Yosys from OSS CAD Suite (unpacked to `C:\tools\oss-cad-suite`, not on PATH):

```sh
PATH="/c/tools/oss-cad-suite/bin:/c/tools/oss-cad-suite/lib:$PATH" yosys -s synth/synth_6502_abc.ys
python src/windows.py --netlist build/cpu_abc.json --passes 2 --out build/cpu_abc_opt.json
python src/csim.py --netlist build/cpu_abc_opt.json
```

| Netlist | Gates | Functional test |
|---|---:|---|
| Yosys without ABC | 3,026 | PASS |
| Window CGP on that | 2,609 | PASS |
| **Yosys with ABC** | **2,075** | PASS |
| Window CGP on the ABC netlist, pass 1 (2,018 windows, 17 improved, 25 min) | 2,058 | |
| Window CGP, pass 2 (1,945 windows, 0 improved, 32 min) | **2,058** | **PASS**, identical 96,241,383 cycles |

Conclusion: most of the earlier 13.8% was redundancy any conventional optimiser removes.
On top of ABC, evolution still found **17 gates (0.8%)** that ABC missed, with exact
correctness. That is a real but small gain. With windows of ≤ 10 inputs the search is exhausted
(pass 2 found nothing), so larger windows or don't-cares would be needed to go further.

### Larger windows and don't-cares (stage 3c)

Both runs start from the 2,058-gate netlist, with k = 13 inputs and up to 40 gates per window, 1 pass:

```sh
python src/windows.py --netlist build/cpu_abc_opt.json --passes 1 --k 13 --max-gates 40 --out build/cpu_big.json
python src/windows.py --netlist build/cpu_abc_opt.json --passes 1 --k 13 --max-gates 40 --dont-cares --out build/cpu_big_dc.json
```

| Run | Windows | Improved | Time | Gates | Functional test |
|---|---:|---:|---:|---:|---|
| Larger windows only | 1,978 | 3 | 66 min | 2,055 | PASS, 96,241,383 cycles |
| Larger windows + SAT don't-cares | 1,991 (1,239 had don't-cares) | 11 (1 rejected: loop) | 146 min | **2,027** | **PASS**, 96,241,383 cycles |

Larger windows on their own add almost nothing. The gain comes from the don't-cares: input
combinations of a window that no CPU state can produce. Ignoring them is still exact for every
state and input, not just the ones the test visits (see [src/dontcare.py](src/dontcare.py)).
Two follow-up runs, both starting from the 2,027-gate netlist:

| Run | Windows | Improved | Time | Gates | Functional test |
|---|---:|---:|---:|---:|---|
| Second pass, k = 13, don't-cares | 1,946 | 2 | 102 min | 2,025 | PASS, 96,241,383 cycles |
| k = 15, max 50 gates, don't-cares | 1,952 | 6 (1 rejected: loop) | 161 min | **2,021** | **PASS**, 96,241,383 cycles |

Repeating at k = 13 is nearly exhausted; larger windows still find a little more, but returns
are diminishing (a few gates per multi-hour run).
That looked like **2,075 (ABC) → 2,021 (−2.6%)**, but see the next section: a single ABC
run is not converged, so that baseline was too generous.

### Alternating ABC and windows; a fairer baseline (stage 3d)

[src/reabc.py](src/reabc.py) exports one of our netlists to Verilog and runs ABC on it again
([synth/reabc.ys](synth/reabc.ys)). Control experiment: **ABC alone keeps improving when rerun**
on its own output, so it has to be iterated before it is a fair baseline.

| Line | Gates after each ABC run |
|---|---|
| ABC alone (from the RTL), runs 1–10 | 2,075 → 2,041 → 2,024 → 2,012 → **1,994** → 2,000 → 2,000 → 1,996 → 1,996 → 1,994 |
| Windows result (2,021), then ABC runs 1–6 | 2,005 → 2,003 → 1,995 → 1,992 → **1,985** → 1,989 |

ABC plateaus around 1,994 ± 5. Against that converged baseline the evolved line was only
9 gates ahead, so both were window-optimised again (k = 15, max 50 gates, don't-cares, 1 pass):

| Start | Windows | Don't-cares used | Improved | Time | Gates | Functional test |
|---|---:|---:|---:|---:|---:|---|
| Converged ABC, 1,994 (PASS) | 1,969 | 1,798 | 22 (1 loop rejected) | 182 min | **1,969** | **PASS**, 96,241,383 cycles |
| Evolved line after ABC, 1,985 (PASS) | 1,965 | 1,890 | 12 | 144 min | 1,973 | PASS, 96,241,383 cycles |

**Conclusion:** against a converged ABC, window CGP with SAT don't-cares removes another
**25 gates (−1.3%)**, with exact equivalence for every state and input. That is well outside
ABC's ±5 noise, so it is a real effect. The earlier evolution work did not compound: both lines
end up around 1,970. After repeated ABC, don't-cares apply to over 90% of windows (60% before).
**Round 3 (convergence check):** 8 more ABC runs on the 1,969-gate netlist all made it *worse*
(1,977–1,982), and another window pass (1,864 windows) found 1 gate: **1,968**, PASS with
96,241,383 cycles. Both optimisers are at a local optimum. Best netlist: build/cpu_round3.json.

### Register-state (sequential) don't-cares (stage 3e)

The don't-cares above treat every flip-flop as free. [src/invariants.py](src/invariants.py)
finds facts about the flip-flops that hold in every *reachable* state: candidate 1- and
2-literal clauses from 256 × 2,000 cycles of random simulation (random opcodes, IRQ, NMI, RDY),
then a Houdini-style SAT induction keeps only those that hold in the initial state and survive
one clock cycle with all inputs free. 381 candidates → **322 proven invariants** (mostly
state-machine bits that are never set together), in about 30 s.

```sh
python src/invariants.py --netlist build/cpu_round3.json --out build/cpu_round3.inv.json
python src/windows.py --netlist build/cpu_round3.json --passes 1 --k 15 --max-gates 50 \
       --invariants build/cpu_round3.inv.json --out build/cpu_seqdc.json
```

| Run from 1,968 | Windows with don't-cares | Improved | Time | Gates | Checks |
|---|---:|---:|---:|---:|---|
| k = 15, register invariants | 1,240 of 1,883 | 5 | 165 min | **1,963** | 322/322 invariants still inductive; **PASS**, 96,241,383 cycles |

For comparison, the previous pass without invariants found 1 gate (don't-cares in 920 of 1,864
windows). The invariants help, but only a little: pairwise clauses over flip-flops are weak
facts. **Assumption:** equivalence holds from the all-zero initial state (as in csim.py); a real
6502 powers up with arbitrary register contents. Not yet compared with ABC's own sequential
optimisation (`scorr`).

Final tally: Yosys + ABC once = 2,075; ABC iterated to its plateau = 1,994; plus window CGP with
SAT don't-cares = 1,968; plus register-state don't-cares = **1,963 (−1.6% beyond converged ABC,
−5.4% vs a single ABC run)**. Best netlist: build/cpu_seqdc.json.

### Correction: ABC's `&deepsyn` beats all of this (stage 3f)

"Converged ABC" above means ABC's *default* script, rerun until it stops improving. ABC also
has `&deepsyn`, a much slower randomised search with SAT-based resynthesis. Run once on the
1,994-gate netlist (`reabc.py --abc "abc -g AND,NAND,OR,NOR,XOR,XNOR -script
+strash;&get,-n;&deepsyn,-T,120;&put;&get,-n;&dch,-f;&nf,{D};&put"`):

| | Gates | Check |
|---|---:|---|
| ABC default script, plateau | 1,994 | PASS |
| Our best (window CGP + don't-cares + invariants) | 1,963 | PASS |
| ABC `&deepsyn`, 2 minutes | 1,896 | **PASS**, 96,241,383 cycles |
| ABC `&deepsyn`, 10 minutes | 1,865 | |

So the −1.6% above was measured against a weak baseline. A stronger ABC command, given a few
minutes, removes 5–6% where our windows found 1.6%. **The window CGP does not beat ABC.**

Does it add something *on top of* deepsyn? Deepsyn 10 minutes, then three more 5-minute runs,
from both starting points (`results/logs/deepsyn-arlet.log`, `deepsyn-arlet-iter.log`):

| Start | deepsyn 10 min | + 5 min | + 5 min | + 5 min |
|---|---:|---:|---:|---:|
| ABC default plateau (1,994) | 1,865 | 1,855 | **1,837** (PASS) | 1,844 |
| Our evolved netlist (1,963) | 1,828 (PASS) | **1,822** (PASS) | 1,829 | 1,825 |

Starting from the evolved netlist, deepsyn ends 10–30 gates lower every time, about 1%.
Plausible reason: the register-state invariants (stage 3e) are sequential facts that
deepsyn, a purely combinational optimiser, cannot discover itself. So the best result,
**1,822 gates**, comes from the combination: ABC, window CGP with SAT and register-state
don't-cares, then deepsyn. The evolution's own share is small (about 1%), and deepsyn's run
to run noise is about ±10 gates, so this is a modest but repeated effect, not a proof.
Lesson, again: a baseline is only fair if the strongest available settings of the tool were
tried, not just its default script iterated.

Non-convex windows can create a combinational loop when spliced; such replacements are
detected and rolled back.

## Modern tools versus the real 1975 6502 (stage 4)

The real 6502's transistor netlist (visual6502, via perfect6502; CC BY-NC-SA 3.0, see
`vendor/perfect6502/COMMIT`) has 3,288 enhancement transistors + 1,018 depletion pull-ups
= **4,306 transistors**. To compare fairly, our netlists are mapped by ABC onto an NMOS cell
library, with transistors as the cost:

```sh
python src/nmos.py                                  # analyse the real chip
python src/nmos_map.py --netlist build/cpu_abc_x10.json
```

| Design | NMOS transistors |
|---|---:|
| Yosys + ABC once | 5,949 |
| ABC iterated (best automated result) | 5,847 |
| Our evolved netlist (fewest two-input gates) | 5,918 |
| Evolved with an NMOS cost (`windows.py --cost nmos`) | 5,878 |
| ABC iterated, mapped with `amap` instead of `map -a` | 5,304 |
| Evolved + `&deepsyn` + `amap`, then cell-level window CGP (best) | **4,867** |
| **Real 6502, hand layout 1975** | **4,306** |

The first rows use ABC's `map -a`; its area mapper `amap` and `&deepsyn` do much better (see
[docs/real6502.md](docs/real6502.md)). With the best flow the automated design is 13% larger
than the hand design (first measured as 36% with the weaker settings). The hand design wins mainly through pass-transistor logic, precharged buses,
the decode PLA and large complex gates. Also: fewer two-input gates is not fewer transistors.
With `map -a`, our evolved netlist loses to ABC once both are counted in NMOS (with deepsyn and `amap` it ends 49 transistors ahead: 4,872 vs 4,921). Evolving with a transistor
estimate as the cost instead of gates helps (5,918 → 5,878, and without ABC's restructuring
5,944 → 5,916), but ABC's own mapping of its iterated netlist stays best. Details and caveats (for
example, Arlet's core is not cycle-exact and has no clock generator or pin drivers) are in
[docs/real6502.md](docs/real6502.md).

We also converted the real 6502's transistor netlist mechanically into ordinary gates
(`src/real6502.py`): pass transistors, precharged buses and stored charge become static
logic plus "settling" registers. After one ABC run the model has 8,888 gates and 556
registers. It runs in lockstep with perfect6502 and passes Klaus Dormann's complete
functional test (96,241,378 cycles, 6 h 18 min in C).
Optimising that model with the same method (ABC to its plateau of 7,416 gates, then window
CGP and ABC again) gives 7,150 gates, −3.6% beyond converged ABC. It runs in lockstep with
perfect6502 and passes the full functional test.

## Roadmap

1. Evolve small combinational blocks (adders, ALU slice) from random and from seeds. **Done.**
2. Obtain a gate-level 6502 netlist (synthesise an existing Verilog 6502 with Yosys). **Done.**
3. Optimise the netlist with seeded CGP on small windows, each checked exhaustively. **Done:** converged ABC (1,994 gates) → 1,968 with window CGP
   and SAT don't-cares → 1,963 with register-state don't-cares (−1.6% in total). **But** ABC's
   `&deepsyn` reaches 1,896 in 2 minutes and 1,865 in 10 (stage 3f), so this is not a win.
4. Reassemble and validate the whole CPU against Klaus Dormann's 6502 functional test suite.

### Out of scope

We are **not** doing the 6510 (the C64 variant with the on-chip I/O port at $00/$01), nor
other variants such as the 6507. The target is the plain 6502 core only; adding the 6510's
I/O port would be extra logic around the core, not a better test of gate optimisation.
